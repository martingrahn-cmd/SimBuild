# R19 startup attribution and terrain cache

## Scope

R19 first repairs the loading probe so it records production navigation/resource data, module initialization time and selected owner logs. The measured production baseline reaches the main menu at 3.21–3.37 seconds. Terrain is the dominant owner at 1.83–1.88 seconds; its 1024² land-cover generation takes about 1.09 seconds. Props and Audio follow at roughly 0.4 and 0.3 seconds.

The accepted candidate caches the tiny deterministic set of Worley field feature positions, orientations and field attributes used across the complete land-cover texture. It does not change resolution, noise, sampling, output channels, texture settings, RNG order outside those coordinate hashes, terrain geometry or save state.

## Verification

- `tools/terrain-landcover-cache-probe.mjs`: PASS. All 4,194,304 generated bytes are exact for seed 1337 (`7f837a…d8ef`) and seed 7 (`f86a45…505`).
- Interleaved six-run Node benchmark: baseline median 1,408.8ms; candidate median 1,254.6ms, a 10.9% reduction for the isolated 1024² generator.
- Production browser logs: the same land-cover stage moves from 1,087ms to 1,006–1,016ms. Total menu readiness remains noisy at 3.30–3.79 seconds, so R19 does not claim the full cold-start gate is closed.
- Matched accepted-source and candidate building-aerial captures are pixel exact by ImageMagick MAE (`0 (0)`). Candidate: 60.4fps, 183 draws, 1,029,476 triangles, errors=0.
- `npm run build`: PASS, Vite 8.2.2, 164 modules.
- `node src/modules/simulation/selftest.mjs 90 1337`: deterministic repeat and exact save/load PASS.

## Decision

Accept the byte-exact owner-local cache and the improved attribution tool. The stage-level reduction is reproducible without visual or simulation change. The overall loading issue remains open because end-to-end readiness did not improve beyond run variance.
